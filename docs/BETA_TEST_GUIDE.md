# Finance Assistant 첫 외부 Beta 테스트 가이드

> 권장 시간: 10~20분
>
> 방식: 처음 보는 사용자를 관찰하는 1:1 테스트
>
> 목표: 기능을 설명하는 것이 아니라 사용자가 스스로 목적·업로드·결과·Forecast를 이해하는지 확인

## 1. 테스트 전 준비

진행자는 다음을 준비합니다.

- 현재 `main`이 반영된 실제 Production URL
- 답변을 받을 외부 채널(대면 메모, 통화, 메신저 등)
- 공개 샘플 Excel·CSV의 다운로드와 분석 성공 확인
- 기록용 [`BETA_TEST_RESULTS.md`](./BETA_TEST_RESULTS.md)
- 문제 기록용 [`BETA_ISSUE_TEMPLATE.md`](./BETA_ISSUE_TEMPLATE.md)

Production URL과 피드백 채널은 repository에 확정되어 있지 않습니다. 임의의 주소나 이메일을 넣지 말고 초대자가 실제 값을 확인해 별도로 전달합니다.

## 2. 개인정보 원칙

첫 Beta에서도 실제 재무정보를 수집하거나 repository에 저장하지 않습니다.

수집하지 않는 정보:

- 이름, 사업자명, 사업자등록번호
- 계좌번호, 카드번호
- 실제 거래처명과 거래 적요
- 실제 개별 금액과 잔액
- 원본 Excel·CSV 파일과 전체 거래내역

사용자는 자신의 파일을 본인의 기기에서 사용할 수 있지만 개발자에게 파일을 보내지 않습니다. 문제 발생 시에는 OS, 브라우저, 파일 확장자, 대략적인 거래 건수 범위, 잔액 컬럼 유무, 오류 메시지와 발생 화면만 확인합니다. 스크린샷은 개인정보와 재무정보를 제거할 수 있을 때만 받습니다.

앱은 원본 파일을 외부 분석 서버로 전송하지 않고 현재 브라우저에서 분석합니다. 원본 거래내역과 분석 결과는 브라우저 저장소에 저장하지 않지만, 선택한 예상 범위와 확정 예정 거래는 파일명을 기준으로 브라우저에 저장될 수 있습니다. 직접 입력 잔액은 현재 세션의 Forecast 시작점으로만 사용되고 저장되지 않습니다.

## 3. 진행자 원칙

- 기능과 화면 위치를 먼저 설명하지 않습니다.
- `여기에 CSV를 넣으세요`, `이게 Forecast입니다`, `보수를 눌러보세요`처럼 답을 유도하지 않습니다.
- 사용자가 막히면 5~10초 관찰한 뒤 `어떻게 하면 될 것 같아요?`라고 중립적으로 묻습니다.
- 계속 막힐 때만 `샘플 데이터로 먼저 해봐도 됩니다.`처럼 최소 힌트를 줍니다.
- 도움을 줬다면 `none / minor / major` 중 하나로 기록합니다.
- 실제 행동(Observation)과 사용자가 말한 의견(Opinion)을 구분합니다.
- 사용자 반응과 성공 여부를 추정해서 기록하지 않습니다.

## 4. 10~20분 진행 순서

### A. 첫 화면

Production 첫 화면만 보여주고 묻습니다.

> 이게 어떤 서비스 같아 보여요?

답변을 기록한 뒤 다음 말만 합니다.

> 처음 보는 서비스라고 생각하고 한번 사용해보세요.

관찰 항목:

- 서비스 목적을 대략 이해하는가
- Sample file과 Upload 영역을 찾는가
- `.xlsx`·`.xls`·`.csv`, 최대 10MB 안내를 이해하는가
- 브라우저 중심 처리와 개인정보 안내를 인지하는가

가능하면 `landing → first upload` 시간을 대략 기록합니다.

### B. 공개 샘플

사용자가 막힐 때만 `샘플 데이터로 먼저 해봐도 됩니다.`라고 말합니다.

확인 항목:

- 샘플 Excel 또는 CSV 다운로드 성공
- 업로드 성공과 자동 분석 완료
- Blocking 오류 없음
- 주요 Dashboard 표시
- `upload → first result` 시간

공개 샘플 canonical 값:

| 항목 | 기대값 |
| --- | ---: |
| 총 입금 | 2,850,000원 |
| 총 출금 | 4,347,000원 |
| 순현금흐름 | -1,497,000원 |
| 최근 잔액 | -497,000원 |
| 보수 3개월 말 잔액 | 277,491원 |
| 기준 3개월 말 잔액 | 456,000원 |
| 낙관 3개월 말 잔액 | 634,509원 |

값이 다르거나 주요 계산이 잘못되면 Beta를 진행하지 않고 P1 blocker로 기록합니다.

### C. 결과와 Forecast 이해

결과가 나타난 직후 묻습니다.

> 여기서 제일 먼저 눈에 들어오는 숫자나 내용이 뭐예요?

답을 유도하지 않고 사용자가 먼저 본 항목을 기록합니다. 이후 묻습니다.

> 향후 3개월 전망은 어떤 의미라고 이해했어요?

미래 현금 잔액의 예상이라는 점, 확정 숫자로 오해하는지, 과거 실적과 Forecast를 구분하는지, 세 예상 범위의 차이를 이해하는지 관찰합니다.

### D. 예상 범위와 Action Guide

다음 질문으로 사용자가 시나리오를 스스로 찾는지 관찰합니다.

> 앞으로 상황이 더 안 좋을 때 결과도 볼 수 있을까요?

> 반대로 더 좋은 경우는요?

이후 묻습니다.

> 이 화면을 보고 지금 뭘 해야 한다고 느껴져요?

Action Guide 발견 여부, 이해도와 금융 조언이 지나치게 확정적으로 느껴지는지를 기록합니다.

### E. 사용자 자신의 파일(선택)

샘플 분석 후 제안만 하며 강제하지 않습니다.

> 본인이 가지고 있는 거래내역 파일로도 한번 해볼래요?

기록할 수 있는 정보는 다음뿐입니다.

- 파일 형식: CSV / XLSX / XLS
- 대략적인 거래 건수: `<100 / 100~500 / 500~1,000 / 1,000+`
- 잔액 컬럼: `yes / no / unknown`
- 자동 시트 탐지·자동 매핑 성공 여부
- Blocking·Partial·미래 거래·무잔액 경고 발생 여부

실제 데이터 내용, 금액, 잔액과 원본 파일은 기록하지 않습니다. 오류 메시지만 보고 사용자가 스스로 복구 가능한지도 관찰합니다.

자동 분석 실패로 직접 설정이 필요한 경우에만 수동 매핑을 관찰합니다. 먼저 설명하지 않고 사용자가 `자동 인식 수정`과 시트·헤더·컬럼 설정을 찾는지 봅니다. 필요하지 않은 사용자에게 억지로 수행시키지 않습니다.

### F. 잔액 컬럼이 없는 파일(해당할 때만)

Forecast 제한 이유, 현재 잔액 직접 입력 발견 여부, 직접 입력값을 과거 실적에 추가되는 금액으로 오해하는지, Forecast 시작 잔액이라는 점을 이해하는지 관찰합니다.

직접 잔액을 사용했다면 묻습니다.

> 여기서 말하는 현재 잔액은 어떤 시점의 금액이라고 이해했어요?

기대 방향은 지금·오늘·현재 사용할 수 있는 잔액입니다. 실제 잔액 값은 기록하지 않습니다. `잔액 확인 날짜` 기능은 만들지 않고 혼동 여부만 기록하며, 혼동이 반복될 때만 향후 개선 후보로 검토합니다.

### G. 예정 거래와 PDF

Forecast를 이해한 뒤 묻습니다.

파일에 미래 날짜 거래가 있다면 자동 반영 안내와 상세 내역을 스스로 발견하는지, 기간 밖 거래와 현재 반영 거래를 구분하는지, 한 건을 제외하고 다시 포함할 수 있는지 먼저 관찰합니다.

> 앞으로 확실히 들어오거나 나갈 돈이 있다면 반영할 수 있을까요?

파일에 없는 확정 예정 거래를 직접 추가하는 기능을 스스로 찾는지 봅니다. 파일에서 자동 반영된 같은 거래를 다시 추가하면 중복될 수 있다는 안내를 이해하는지도 관찰합니다. 테스트 금액은 합성 값 또는 사용자가 직접 입력한 값으로 사용하고 실제 금액은 기록하지 않습니다.

마지막에 묻습니다.

> 이 결과를 다른 사람에게 전달하려면 어떻게 할 것 같아요?

PDF·인쇄 기능 발견 여부를 기록하되, 못 찾았다는 이유만으로 전체 사용성 실패로 판단하지 않습니다.

## 5. 핵심 인터뷰 질문 6개

1. 처음 봤을 때 어떤 서비스라고 생각했나요?
2. 어떤 Excel/CSV를 올려야 하는지 알 수 있었나요?
3. 본인의 파일을 정상적으로 분석할 수 있었나요?
4. 결과 화면에서 가장 먼저 눈에 들어온 정보는 무엇이었나요?
5. 이해하기 어렵거나 불편했던 부분은 무엇이었나요?
6. 다음 달에도 사용할 것 같나요? 그 이유는 무엇인가요?

필요한 경우에만 앞 단계의 중립적인 follow-up을 추가합니다. Yes/No보다 이유를 우선 기록합니다.

## 6. 완료 후 기록

- 총 테스트 시간을 대략 기록합니다. 사용자가 부담스러워하면 생략할 수 있습니다.
- 결과는 [`BETA_TEST_RESULTS.md`](./BETA_TEST_RESULTS.md)에 익명으로 기록합니다.
- 개별 문제는 [`BETA_ISSUE_TEMPLATE.md`](./BETA_ISSUE_TEMPLATE.md)에 기록합니다.
- 실제 사용자 파일 구조의 호환성 결과만 [`EXCEL_COMPATIBILITY.md`](./EXCEL_COMPATIBILITY.md)에 비식별 형태로 기록합니다.
- 기능 요청은 즉시 구현하지 않고 3~5명 중 반복되는지 확인합니다.

월별 주요 지출 화면의 길이, 잔액 기준 날짜, 원본 분류 보존은 현재 구현하지 않습니다. 실제 사용자가 혼동이나 필요를 표현했는지만 기록합니다.
